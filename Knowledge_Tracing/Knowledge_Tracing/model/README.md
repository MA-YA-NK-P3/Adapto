# `model/` — offline research package (Python)

The **live** models (IRT, concept mastery, gap detection, localization, recommendation,
decision layer, DKT inference) run inside the Java backend. This folder holds the offline work:

| Path | Purpose |
|---|---|
| `kt/irt.py`, `kt/mastery.py`, `kt/catalog.py` | Reference ports of the backend models (same formulas, same constants) |
| `kt/synthetic.py` | Synthetic learner simulator over the 28 seed problems — **SYNTHETIC / DEVELOPMENT DATA** |
| `kt/simulator.py`, `kt/events.py` | Simulator v2 over the 1000-problem catalog and the `kt-events-v1` format — **SYNTHETIC / DEVELOPMENT DATA** |
| `kt/metrics.py` | Accuracy, AUC, log loss, Brier, ECE, MAE, RMSE, Spearman |
| `kt/predictors.py` | Next-response predictors: static, success-rate, IRT, IRT+graph, IRT+KT, full |
| `kt/policies.py` | Next-problem policies: random, static ladder, success-rate, system with ablation flags |
| `kt/dkt.py` | Minimum-data rule and availability report for DKT |
| `dkt/features.py`, `dkt/dkt_model.py`, `dkt/data.py`, `dkt/train_dkt.py` | DKT (`kt-dkt-v1`): feature contract + stdlib reference forward pass, PyTorch LSTM, training windows, training/export ([docs/dkt.md](../docs/dkt.md)) |
| `dkt/make_fixture.py` | Java/Python DKT parity fixture for `DktModelTest` |
| `artifacts/dkt/` | Trained model: `dkt-model.json` (loaded by the backend), `dkt-model.pt`, `history.json`, `metrics.json` — trained on **synthetic** data |
| `evaluation/run_evaluation.py` | Baselines, policy simulation + ablation → `reports/evaluation-report.md` |
| `evaluation/evaluate_kt.py` | Held-out evaluation of all KT models incl. DKT → `reports/kt-evaluation.md`, `reports/figures/` |
| `jev/` | Offline mirror of the Jev providers (LinUCB, deterministic) → `reports/jev-simulation.md` |
| `reports/` | Generated reports and figures ([docs/evaluation.md](../docs/evaluation.md)) |
| `tests/` | `unittest` suite |
| `pylib/` | Project-local install target for PyTorch, NumPy, matplotlib (not required for most code) |

Requirements: Python ≥ 3.9. Everything except DKT training and the figures is
**standard library only**; DKT training needs `requirements-dkt.txt` (`torch`, `numpy`,
`matplotlib`), installed into `model/pylib`. Local convention: run from `model/` with
`PYTHONPATH=pylib:.`.

```bash
python3 -m pip install --target model/pylib -r model/requirements-dkt.txt   # once, from the repository root

cd model
PYTHONPATH=pylib:. python3 -m unittest discover -s tests -t .          # 66 tests
PYTHONPATH=pylib:. python3 evaluation/run_evaluation.py                # writes data/synthetic/ + reports/
PYTHONPATH=pylib:. python3 ../scripts/generate_synthetic_dataset.py    # data/synthetic/v2 (2500 learners)
PYTHONPATH=pylib:. python3 dkt/train_dkt.py --allow-synthetic          # trains + exports artifacts/dkt/
PYTHONPATH=pylib:. python3 evaluation/evaluate_kt.py                   # reports/kt-evaluation.md + figures
PYTHONPATH=pylib:. python3 jev/simulate_jev.py                         # reports/jev-simulation.md
PYTHONPATH=pylib:. python3 ../scripts/replay_synthetic.py              # end-to-end against a running backend
python3 ../scripts/export_catalog.py                                   # refresh data/seed/catalog.json from the backend
```

Without PyTorch, `train_dkt.py` prints an availability report instead of training.

Google Colab: `notebooks/DKT_train_and_visualize.ipynb` and
`notebooks/Jev_bandit_simulation.ipynb` are self-contained (they embed this package and the
1000-problem catalog). They are generated by `python3 scripts/build_colab_notebooks.py`
(repository root; `--smoke` also executes them locally); regenerate after changing any
bundled file.

All numbers produced here come from simulators whose assumptions are documented in
`kt/synthetic.py`, `kt/simulator.py`, `docs/data.md` and `docs/evaluation.md`. They validate
implementation behaviour, not real learning outcomes.
